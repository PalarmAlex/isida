1. ОБЗОР И НАЗНАЧЕНИЕ
--------------------

Три каталога реализуют подсистемы психики агента:
  • Importance  — значимость объектов восприятия (на основе эпизодической памяти).
  • Memory      — моторная эпизодическая память (правила «стимул → действие», история кадров).
  • Understanding — понимание ситуации (дерево понимания, дерево проблем, образы ситуаций).

Все они активны начиная с 4-й стадии развития (EvolutionStage >= 4) и встроены в контур реагирования через PsychicSystem, OrientationReflexSystem и AutomatismResultTracker.


2. КАТАЛОГ Psychic\Importance
-----------------------------

2.1. Классы
  • ExtremImportance       — DTO: ID объекта (ActionsImage) и экстремальная значимость (-10..10).
  • ObjectImportanceService — статический сервис: вычисление значимости по эпизодической памяти и обновление «текущего самого значимого объекта» в информационной среде.

2.2. Назначение
  • Определять значимость образа действия/стимула (ActionsImage ID) в контексте текущих условий (BaseID, EmotionID, NodePID).
  • Выделять «самый значимый объект» текущего восприятия и записывать его в InformationEnvironment.ExtremImportanceObjectID.
  • Поддерживать проверку новизны (IsUnknownActionsImage), выбор лучшего правила по важности (GetBestRuleFromImportants) и лучшего положительного действия из учительских правил (FindBestPositiveAction).

2.3. Когда и как активируются
  • UpdateExtremImportanceObject вызывается из OrientationReflexSystem при срабатывании ориентировочного рефлекса 1 и 2 уровня (ОР1, ОР2) — т.е. при появлении стимула, когда нужно обновить информационную среду и выделить объект максимальной значимости.
  • Условие: EvolutionStage >= 4, инициализированы EpisodicMemorySystem и InformationEnvironmentSystem.
  • Пороги: MinSignificantImportance = 2 (|ExtremVal| > 2 — достаточно значимый объект), HighImportanceThreshold = 3 (для возможной смены темы и т.п.).

2.4. Связи
  • Читает данные из EpisodicMemorySystem (дерево эпизодов, TreeLogic), записывает результат в InformationEnvironmentSystem (CurrentInformationEnvironment.ExtremImportanceObjectID).
  • Использует условия из эпизодической памяти: BaseID (гомеостаз: -1/0/1), EmotionID (из информационной среды), NodePID (ID узла дерева проблем из ProblemTreeSystem).


3. КАТАЛОГ Psychic\Memory (Episodic)
------------------------------------

3.1. Классы
  • EpisodicMemoryNode   — узел дерева: BaseID, EmotionID, NodePID, TriggerId, ActionId, Params (Effect, Count, StimulsEffect).
  • EpisodicParams       — Effect (-10..10 или 100 для учительского), Count, StimulsEffect.
  • EpisodicHistoryEntry / EpisodicMemoryHistory — лента кадров (NodeId, LifeTime), разрывы цепочки (NodeId = -1).
  • EpisodicRule         — правило для поиска: TriggerId, ActionId, Effect, Count, Importence.
  • EpisodicMemoryTree   — логика дерева: поиск/доращивание веток по условиям, усреднение эффекта при повторе.
  • EpisodicMemoryStorage — загрузка/сохранение дерева и истории в файлы.
  • EpisodicMemorySearch  — поиск правил по условиям, GetTargetChain (цепочка с позитивным концом), GetSingleBestRule.
  • EpisodicMemoryRulesService — запись правил: FixDirectRule (после отслеживания результата), FixTeacherRule (при распознавании ответа оператора), SetInterruption (конец темы).
  • EpisodicMemorySystem — единая точка входа: инициализация, текущие условия (GetCurrentConditions), SaveNewEpisode, History, поиск правил (GetTargetChain, GetSingleBestRule).

3.2. Назначение
  • Хранить моторную эпизодическую память: в каких условиях (BaseID, EmotionID, NodePID) какой стимул (TriggerId) приводил к какому действию (ActionId) и с каким эффектом (Effect, StimulsEffect).
  • Ведение истории кадров для построения цепочек «стимул → действие → … → позитивный исход» (GPT-цепочка).
  • Запись прямых правил (по результату выполнения автоматизма) и учительских правил (оценка оператора).

3.3. Когда и как активируются
  • Инициализация: IsidaEngine, шаг 27 — EpisodicMemorySystem.InitializeInstance(psychicDataPath, AutomatizmTree, ProblemTree, InformationEnvironment, Gomeostas, ActionsImages). Затем создаётся EpisodicMemoryRulesService и передаётся в AutomatismResultTracker.
  • Запись эпизодов:
    - FixDirectRule — из AutomatismResultTracker при завершении отслеживания результата (FinishTracking): triggerId = стимул, actionId = результат, effect = usefulnessDelta, stimulsEffect.
    - FixTeacherRule — при распознавании ответа оператора (MarkOperatorRecognition): triggerId = ответ оператора, actionId = ответ агента, Effect = 100.
    - SetInterruption — конец темы (пустой кадр в истории).
  • Чтение:
    - GetCurrentConditions(baseId, emotionId, nodePid) — используются гомеостаз, информационная среда (PsyEmotionId), дерево проблем (DetectedActiveLastProblemNodeId).
    - GetSingleBestRule(typeRule, triggerId) — вызывается из PsychicSystem при выборе действия по стимулу (stage >= 4): предпочтительное действие из эпизодов (preferredActionIdFromEpisodic).
    - GetTargetChain(triggerId) — при отсутствии готового автоматизма на стимул: цепочка правил с позитивным концом; по ней выбирается правило и при необходимости создаётся автоматизм по rule.ActionId.

3.4. Связи
  • Зависит от: AutomatizmTreeSystem, ProblemTreeSystem, InformationEnvironmentSystem, GomeostasSystem, ActionsImagesSystem.
  • Поставляет данные для: ObjectImportanceService (дерево и условия), PsychicSystem (поиск правил и цепочек), AutomatismResultTracker (запись через EpisodicMemoryRulesService).
  • NodePID в дереве эпизодов = DetectedActiveLastProblemNodeId из ProblemTreeSystem (при useOldCondition — OldDetectedActiveLastProblemNodeId для учительских правил).


4. КАТАЛОГ Psychic\Understanding
---------------------------------

4.1. Классы
  • UnderstandingTreeNode / UnderstandingTreeSystem — дерево понимания ситуации: 3 уровня (Mood, EmotionId, SituationId). Активируется после дерева автоматизмов; выдаёт DetectedActiveLastUnderstandingNodeId и (AutTreeId, SituationTreeId) для дерева проблем.
  • SituationImageRecord / SituationImageSystem    — образ ситуации: пара (AutomatizmTreeNodeId, SituationTypeId). GetCurSituationImageId(automatizmTreeNodeId) — текущий образ для активации Understanding (упрощённо: тип 4 «Experiment»).
  • SituationTypeRecord / SituationTypeSystem      — справочник типов ситуаций (Id, Name, Code), по умолчанию: ResponseAction, AutomatizmRun, NeedThinking, Experiment, OperatorIgnore.
  • ProblemTreeNode / ProblemTreeSystem            — дерево проблем: узлы по AutTreeID и при наличии — SituationTreeID (4 уровня: AutTreeID, SituationTreeID, ThemeID, PurposeID). DetectedActiveLastProblemNodeId используется в эпизодической памяти как NodePID.

4.2. Назначение
  • Связать текущий контекст (настроение, эмоция, образ ситуации) с узлом дерева понимания и с узлом дерева проблем.
  • Дерево проблем даёт «текущую проблему/ситуацию» (NodePID) для условной эпизодической памяти и для важности.

4.3. Когда и как активируются
  • Инициализация (IsidaEngine): SituationTypeSystem → SituationImageSystem → ProblemTreeSystem → UnderstandingTreeSystem (шаги 20–22). AutomatizmTree.SetProblemTree(ProblemTree).
  • ActivateSituation вызывается из PsychicSystem в двух точках:
    1) При пробуждении (WakeUpping): после первой активации дерева автоматизмов (AutomatizmTreeActivation) — UnderstandingTreeSystem.Instance.ActivateSituation(1, wakeNodeId, baseId, emotionId, ProblemTreeSystem.Instance).
    2) При сенсорной активации (SensorActivation): после активации дерева автоматизмов по стимулу — ActivateSituation(activationType, automatizmNodeId, currentBaseId, currentEmotionId, ProblemTreeSystem.Instance).
  • В ActivateSituation: по SituationImageService.GetCurSituationImageId(automatizmTreeNodeId) получается образ ситуации; по (Mood, EmotionId, SituationId) находится или достраивается ветка Understanding; обновляется ProblemTreeInfo и problemTree.UpdateActiveBranchFromUnderstandingInfo(automatizmTreeNodeId, situationImageId). При situationImageId = 0 вызывается UpdateActiveBranchFromUnderstandingInfo(automatizmTreeNodeId, 0) (упрощённый режим).

4.4. Связи
  • Understanding зависит от SituationImageService → SituationImageSystem и SituationTypeSystem; обновляет ProblemTreeSystem.
  • ProblemTreeSystem обновляется только из UnderstandingTreeSystem.ActivateSituation (и при отсутствии полного Understanding — по AutomatizmTree через UpdateActiveBranchFromAutomatizmTree).
  • EpisodicMemorySystem и ObjectImportanceService используют ProblemTreeSystem.DetectedActiveLastProblemNodeId как NodePID в условиях поиска/записи.


5. ВСТРОЙКА В СИСТЕМУ РЕАГИРОВАНИЯ АГЕНТА
-----------------------------------------

5.1. Последовательность при поступлении стимула (SensorActivation)
  1) Создание образов: InfluenceActionsImage, EmotionsImage, ActionsImage (actionsImageId).
  2) Активация дерева автоматизмов: AutomatizmTreeActivation(...) → automatizmNodeId.
  3) Активация понимания ситуации: UnderstandingTreeSystem.ActivateSituation(...) → обновление дерева проблем (DetectedActiveLastProblemNodeId).
  4) При ожидании оценки оператора — регистрация ответа или сброс.
  5) Для stage >= 4 и при наличии эпизодической памяти:
     - GetSingleBestRule(3, actionsImageId) → preferredActionIdFromEpisodic для выбора/приоритета автоматизма.
     - Если автоматизм не найден — GetTargetChain(actionsImageId), иначе GetSingleBestRule(3, actionsImageId); по правилу при необходимости создаётся автоматизм по rule.ActionId и выполняется.
  6) Ориентировочный рефлекс (при необходимости): OrientationReflex_1 / OrientationReflex_2 → GetCurrentInformationEnvironment(...), затем ObjectImportanceService.UpdateExtremImportanceObject(...) → обновление ExtremImportanceObjectID в информационной среде.

5.2. Запись эпизодов
  • Прямое правило: после выполнения автоматизма и оценки полезности — AutomatismResultTracker вызывает EpisodicMemoryRulesService.FixDirectRule(triggerId, actionId, usefulnessDelta, stimulsEffect).
  • Учительское правило: при признании ответа оператора — FixTeacherRule(operatorResponseActionsImageId, result.ActionsImageId, PrevStimulsEffect) (с useOldCondition при записи).

5.3. Инициализация (порядок в IsidaEngine)
  SituationTypeSystem → SituationImageSystem → ProblemTreeSystem → UnderstandingTreeSystem → … → EpisodicMemorySystem(EpisodicMemoryRulesService) → PsychicSystem → … → SetPsychicSystemDop(..., EpisodicMemorySystem). OrientationReflexSystem получает эпизодическую память и информационную среду через свои зависимости.


6. КРАТКАЯ СВОДКА ПО ОТВЕТСТВЕННОСТИ
-------------------------------------

  • Importance (ObjectImportanceService, ExtremImportance):
    — Определение значимости образа действия по эпизодической памяти в текущих условиях.
    — Выделение текущего «самого значимого объекта» и запись в информационную среду; пороги значимости; новизна и выбор лучшего правила/действия по важности.
    — Активация: при срабатывании ОР1/ОР2 (OrientationReflexSystem), при каждом новом стимуле после установки ActionsImageID (при stage >= 4).

  • Memory (Episodic):
    — Хранение и поиск правил «условия + стимул → действие» с эффектом и значимостью стимула; история кадров для цепочек.
    — Запись прямых и учительских правил; поиск лучшего правила и цепочки с позитивным исходом для выбора/создания автоматизма.
    — Активация: запись — из AutomatismResultTracker; чтение — из PsychicSystem (выбор действия) и ObjectImportanceService (значимость и условия). Условия (BaseID, EmotionID, NodePID) берутся из гомеостаза, информационной среды и дерева проблем.

  • Understanding (UnderstandingTree, ProblemTree, SituationImage, SituationType):
    — Классификация текущей ситуации (настроение, эмоция, образ ситуации) и актуализация узла дерева проблем (NodePID).
    — NodePID используется эпизодической памятью и важностью как часть контекста.
    — Активация: после каждой активации дерева автоматизмов — из PsychicSystem (при пробуждении и при SensorActivation).

  • Связь трёх подсистем:
    Understanding обновляет ProblemTree → EpisodicMemory и Importance используют NodePID из ProblemTree. Importance и выбор действия в PsychicSystem опираются на данные EpisodicMemory. Всё завязано на стадию 4 и выше и на единый контур: стимул → дерево автоматизмов → понимание ситуации → дерево проблем → эпизодическая память (чтение/запись) и значимость (обновление объекта в информационной среде).
