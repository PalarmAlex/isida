ОТЧЁТ ПО АНАЛИЗУ ЭПИЗОДИЧЕСКОЙ ПАМЯТИ (Psychic\Memory)
Проект: ISIDA. Дата: 09.03.2025
================================================================================

1. ИСПОЛЬЗОВАНИЕ МЕТОДОВ КЛАССОВ, ПОСЛЕДОВАТЕЛЬНОСТЬ, ОТВЕТСТВЕННОСТЬ
--------------------------------------------------------------------------------

• EpisodesTreeSystem (EpisodesTree.cs)
  - Singleton, точка входа в дерево эпизодов.
  - InitializeInstance() — инициализация, загрузка дерева из файла.
  - GetEpisodesTree() — доступ к корню дерева.
  - AddEpisode(), SaveEpisode() — добавление и сохранение эпизода.
  - FindEpisode(), GetEpisodeByID() — поиск по дереву и по ID.
  - ActivateEpisodesBranch() — активация ветки по контексту (ID активности, тона и т.д.).
  - GetLastEpisodeID(), GetNewEpisodeID() — управление ID.
  Ответственность: хранение дерева эпизодов, поиск по контексту, выдача активной ветки.

• Episode (Episode.cs)
  - Модель одного эпизода: ID, ParentID, EmotionID, ActivityID, ToneMoodID, SimbolID, VerbID, время, флаги.
  - Связь с действием (ActionID) и с автоматизмом (AutomatizmID).
  Ответственность: данные одного эпизода, без логики.

• EpisodeNode (EpisodesTree.cs)
  - Узел дерева: те же поля, что у Episode, плюс Children, ParentNode.
  - Используется только внутри EpisodesTreeSystem для обхода дерева.
  Ответственность: узел дерева для навигации.

• MentalEpisode, MentalRule (Mental\*.cs)
  - MentalEpisode — эпизод с ментальным контекстом (понимание).
  - MentalRule — правило реагирования, связь TriggerID -> ActionID.
  - Хранятся в списках, сериализация в JSON. Методы Add, GetByID, SaveRules.
  Ответственность: ментальные правила и эпизоды (зависимость от Understanding).

Последовательность при записи эпизода:
  1) EpisodesTreeSystem.AddEpisode() создаёт Episode и EpisodeNode.
  2) Сохранение в файл через SaveEpisode().
  3) При наличии понимания — MentalEpisode/MentalRule могут дополняться (сейчас не вызываются из основного потока).

Последовательность при поиске/реакции:
  1) Вызов ActivateEpisodesBranch(activityID, toneMoodID, ...) по текущему контексту.
  2) Получение активной ветки (узлов) для выбора эпизода или правила.
  3) GetEpisodeByID() при необходимости получения полного эпизода.


2. ТОЧКИ ВХОДА В ЭПИЗОДИЧЕСКУЮ ПАМЯТЬ
--------------------------------------------------------------------------------

• Явная инициализация:
  - EpisodesTreeSystem.InitializeInstance(psychicDataPath) — из PsychicContext или при старте приложения.

• Запись эпизода:
  - EpisodesTreeSystem.Instance.AddEpisode(...) — должен вызываться после произошедшего события (действие + контекст + результат).
  - В проекте вызовов AddEpisode() не найдено — точка входа не подключена.

• Активация ветки (поиск по контексту):
  - EpisodesTreeSystem.Instance.ActivateEpisodesBranch(activityID, toneMoodID, emotionID, simbolID, verbID).
  - Вызовов ActivateEpisodesBranch() в коде не найдено — не используется при принятии решений.

• Чтение эпизода по ID:
  - EpisodesTreeSystem.Instance.GetEpisodeByID(id).

• Ментальные правила:
  - MentalRulesStorage.GetRules(), AddRule(), SaveRules() — точки входа есть, но из основной логики не вызываются.

Вывод: точки входа в эпизодическую память (AddEpisode, ActivateEpisodesBranch) в коде объявлены, но не вызываются из сценариев диалога или психики, поэтому эпизодическая память в текущем виде не задействована.


3. ФОРМИРОВАНИЕ И ХРАНЕНИЕ ПРАВИЛ РЕАГИРОВАНИЯ
--------------------------------------------------------------------------------

• Эпизоды (базовые):
  - Формируются: через AddEpisode() с параметрами контекста (ActivityID, ToneMoodID, EmotionID, SimbolID, VerbID) и связями ActionID, AutomatizmID.
  - Хранение: дерево в памяти + сериализация в файл (EpisodesTreeSystem), файл episodes_tree в папке Psychic/Episode.

• Правила реагирования (ментальные):
  - MentalRule: TriggerID (ID образа триггера от понимания) -> ActionID (ID действия).
  - Формируются: через MentalRulesStorage.AddRule(triggerID, actionID).
  - Хранение: список в MentalRulesStorage, файл mental_rules.json в Psychic/Mental.
  - Условие: TriggerID опирается на Understanding (образы понимания), поэтому без реализации Understanding ментальные правила не имеют смысла.

• Связь эпизод — автоматизм:
  - В Episode хранится AutomatizmID — уже сформированное правило «в такой ситуации использовать этот автоматизм». Само «правило» — это выбор автоматизма по активной ветке эпизодов (по аналогии с прошлым опытом).


4. СТРУКТУРА ДЕРЕВА ЭПИЗОДИЧЕСКОЙ ПАМЯТИ И СРАВНЕНИЕ С ДЕРЕВОМ АВТОМАТИЗМОВ
--------------------------------------------------------------------------------

• Дерево автоматизмов (AutomatizmTree.cs):
  - Уровни: BaseID -> EmotionID -> ActivityID -> ToneMoodID -> SimbolID -> VerbID (6 уровней).
  - Узлы: AutomatizmNode с полями под каждый уровень и Children.
  - Индексация: _nodesById для доступа по ID; обход по уровням сужает множество кандидатов.
  - Листья/результат: к узлам привязаны автоматизмы (по ID узла), поиск по дереву даёт узел, по нему — автоматизм.

• Дерево эпизодов (EpisodesTree.cs):
  - Та же логика уровней: в EpisodeNode те же поля (BaseID, EmotionID, ActivityID, ToneMoodID, SimbolID, VerbID).
  - Структура дерева идентична по уровням и назначению — контекстное ветвление для быстрого сужения поиска.
  - Нет отдельного словаря _nodesById в коде; есть GetEpisodeByID перебором по дереву (медленнее при большом числе эпизодов).
  - Активация ветки: ActivateEpisodesBranch обходит дерево по уровням, формирует список узлов активной ветки (аналог ActiveBranchNodeArr у автоматизмов).

• Нужно ли хранить эпизодическую память в виде дерева:
  - Да, даёт преимущества: поиск по контексту за O(глубина дерева), как у автоматизмов; единообразие с деревом автоматизмов; возможность выбирать «похожий прошлый опыт» по той же схеме контекста.
  - Рекомендация: оставить дерево; добавить словарь _nodesById для EpisodeNode (по ID узла), чтобы GetEpisodeByID и доступ по ID были O(1).


5. РАБОТА ЭПИЗОДИЧЕСКОЙ ПАМЯТИ БЕЗ ПОЛНОЙ РЕАЛИЗАЦИИ UNDERSTANDING И MENTAL
--------------------------------------------------------------------------------

• Без Understanding и Mental:
  - Базовое дерево эпизодов (EpisodesTreeSystem + Episode) не зависит от Understanding и Mental. Оно опирается на: ActivityID, ToneMoodID, EmotionID, SimbolID, VerbID — эти ID уже есть в текущей модели (образы активности, тона, символа, глагола и т.д.).
  - Эпизодическая память может: записывать эпизоды после действий, активировать ветку по контексту, возвращать эпизоды/узлы для выбора реакции по прошлому опыту (в т.ч. по AutomatizmID).
  - Ментальные правила (MentalRule, MentalEpisode) требуют Understanding: триггер — это ID образа понимания. Без Understanding ментальные правила не имеют смысла, но они не блокируют работу базовой эпизодической памяти.

• Можно ли реализовать ментальные правила потом:
  - Да. Достаточно не вызывать MentalRulesStorage и MentalEpisode из основного потока до готовности Understanding. Базовые эпизоды и дерево эпизодов можно использовать независимо; при появлении Understanding можно будет дописывать ментальные правила и эпизоды без переделки существующего кода дерева.


6. ДОПОЛНИТЕЛЬНЫЕ ВЫВОДЫ ДЛЯ СТРУКТУРНОГО АНАЛИЗА
--------------------------------------------------------------------------------

• Сравнение с BOT (Go):
  - В BOT эпизодическая память вызывается из сценариев (episodeStorage.AddEpisode, GetEpisodeByID, активация по контексту), есть явная интеграция с диалогом и действиями. В isida дерево и классы готовы, но вызовов из сценариев/психики нет — интеграция отсутствует.

• Потокобезопасность:
  - В EpisodesTreeSystem используется ReaderWriterLockSlim при загрузке и при добавлении узлов — этого достаточно при аккуратном использовании из одного потока или при редких записях.

• Сериализация:
  - Дерево сохраняется целиком (в т.ч. список эпизодов). При большом объёме данных можно рассмотреть инкрементальное сохранение или снимки по узлам.

• Зависимости:
  - Psychic\Memory зависит от Understanding только в подсистеме Mental. Основные классы Episode, EpisodesTree, EpisodeNode от Understanding не зависят.

ЗАКЛЮЧЕНИЕ: ЧТО ИСПРАВИТЬ И ДОПОЛНИТЬ ДЛЯ ИСПОЛЬЗОВАНИЯ ЭПИЗОДИЧЕСКОЙ ПАМЯТИ
================================================================================

1. Подключить точки входа в сценарии/психику:
   - После совершения действия и получения контекста вызывать EpisodesTreeSystem.Instance.AddEpisode(...), передавая текущие ActivityID, ToneMoodID, EmotionID, SimbolID, VerbID, выбранный AutomatizmID/ActionID и при необходимости результат (хорошо/плохо).
   - При выборе реакции: вызывать ActivateEpisodesBranch(...) с текущим контекстом, по активной ветке или последнему узлу брать эпизоды и учитывать их при выборе автоматизма (например, предпочитать AutomatizmID из похожего эпизода).

2. Ускорить доступ по ID:
   - В EpisodesTreeSystem вести Dictionary<int, EpisodeNode> _nodesById при добавлении/загрузке узлов и использовать его в GetEpisodeByID вместо обхода всего дерева.

3. Ментальные правила оставить на потом:
   - Не вызывать MentalRulesStorage и MentalEpisode до реализации Understanding; базовую эпизодическую память использовать без них.

4. Инициализация:
   - Убедиться, что EpisodesTreeSystem.InitializeInstance() вызывается при старте приложения вместе с инициализацией дерева автоматизмов (например, из PsychicContext или аналога).

5. Тесты и отладка:
   - Добавить сценарий: запись эпизода после ответа пользователю и повторное использование при похожем контексте (проверка ActivateEpisodesBranch и выбора по прошлому опыту).

После этих шагов эпизодическая память начнёт реально использоваться в проекте isida без необходимости ждать окончательной реализации Understanding и Mental.
