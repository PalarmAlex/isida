1. КАК УСТРОЕНА СИСТЕМА (ПО ДАННЫМ И КОДУ)

1.1. Хранилище на диске
   - ScenarioRegistry.dat — реестр сценариеов (Id, Title, Description, Date, Group, SortInGroup).
   - Scenario_N.dat — тело сценария N: метаданные (SCENARIO_META), таблица шагов, блок
     SCENARIO_LOG_EXPECTATIONS с ожидаемыми значениями колонок журнала по шагам.
   - Примеры в установке: Scenario_1.dat (стадия 3, зеркальные автоматизмы), Scenario_2.dat
     (стадия 1, условные рефлексы).

1.2. Формат строки шага (после заголовка # Step|Pulse|Kind|...):
   Поля: Step | PulseWithinScenario | Kind | ToneId | MoodId | ActionIds | Phrase | ResetWait
   
   - PulseWithinScenario — номер пульса относительно старта прогона; глобальный пульс =
     anchor + PulseWithinScenario (якорь подстраивается под MinGlobalPulseForAutomatizmTreeActivation).
   - Kind: P — воздействие через пульт (фраза и/или ActionIds, опционально ToneId/MoodId);
            W — только имитация клика по плашке ожидания (без фразы и действий).
   - ActionIds — ID воздействий из InfluenceActionSystem (в файле часто одно число или пусто).
   - ResetWait (0/1): на шаге только сброс периода ожидания оценки оператора (со стадии 3,
     не сочетается с фразой/действиями; иначе вызов cancelWaitingPeriod как у клика по плашке).

1.3. Исполнение
   - OperatorScenarioRunner на каждом глобальном пульсе сравнивает счётчик с расписанием;
     для P вызывается IOperatorScenarioPult.TryApplyScenarioStimulus(actions, phrase, tone, mood).
   - OperatorScenarioEngine задаёт зазор между шагами через ReflexActionDisplayDuration;
     ScenarioPulseSchedule пересчитывает пульсы по режиму Sequential / ActionHoldPlusOne /
     StateHoldPlusOne (из шапки сценария).
   - В шапке сценария (в редакторе/метаданных) задаются: целевая стадия перед прогоном, очистка
     данных, режим наблюдения, авторитарная запись фразы и т.д. — это влияет на хост, не меняя
     сам формат одной строки P/W.

1.4. Проверка результата
   - Таблица ожиданий лога (State, Style, Theme, Trigger, OrUm, GenRef, CondRef, Automatizm,
     цепочки, цикл мышления) сопоставляется с отчётом прогона (см. ScenarioLogExpectationModels).

2. УЖЕ ПОКРЫТО СУЩЕСТВУЮЩИМИ ФАЙЛАМИ (КРАТКО)

2.1. Scenario_1.dat — стадия 3, зеркало и сдвиг, сброс ожидания
   Механизм: MirrorAutomatizmService / цепочка диалога с окном ожидания оператора.
   Последовательность (как в файле):
     Шаг 1: пульс 1,  P, фраза «привет», действий нет, ResetWait=0
     Шаг 2: пульс 4,  P, «хай», ResetWait=0
     Шаг 3: пульс 7,  P, «как дела», ResetWait=0
     Шаг 4: пульс 10, P, «все ОК», ResetWait=0
     Шаг 5: пульс 13, P, без фразы и действий, ResetWait=1 (срыв цепочки ожидания)
     Шаг 6: пульс 16, P, «привет», ResetWait=0
     Шаг 7: пульс 19, P, «как дела», ResetWait=0
     Шаг 8: пульс 22, P, «это хорошо», ResetWait=0
   (Интервалы пульсов заданы режимом метаданных + зазор из настроек проекта.)

2.2. Scenario_2.dat — стадия 1, условный рефлекс
   Механизм: ConditionedReflexesSystem + гомеостатическое воздействие с пульта после вербального CS.
   Последовательность:
     Нечётные шаги: пульсы 1,10,19,28,37,46 — P, фраза «Эх», без действий, ResetWait=0
     Чётные шаги:   пульсы 2,11,20,29,38 — P, без фразы, ActionIds=5 (в примере — «Огорчить»),
                    ResetWait=0
     Последний шаг 11: только «Эх» — ожидается срабатывание выученной связи (колонка CondRef в логе).

3. СПИСОК ДОПОЛНИТЕЛЬНЫХ МОДУЛЕЙ, КОТОРЫЕ ИМЕЕТ СМЫСЛ ПРОВЕРЯТЬ ЧЕРЕЗ СЦЕНАРИИ

Во всех предложениях ниже: ToneId/MoodId — по необходимости из справочника проекта (0|0 если
не тестируете просодику); ActionIds — реальные ID из InfluenceActionSystem; пульсы Pulse —
задать в редакторе сценария с выбранным PulseStepIncrement или вручную с возрастанием по шагам.

--------------------------------------------------------------------------------
3.1. Стадия 0 — безусловные (генетические) рефлексы
--------------------------------------------------------------------------------
Механизм: ReflexesActivator / генетические рефлексы на заданные стимулы пульта (не обучение).

Идея сценария: подать с пульта только гомеостатические воздействия (и при необходимости пустую
фразу), совпадающие с UCR из конфигурации агента; в ожиданиях лога проверять столбец GenRef
и смену State/Style.

Пример последовательности строк (шаблон, D — зазор из настроек между шагами):
  1 | 1  | P | 0 | 0 | <ID_напугать> | | 0
  2 | 1+D+1 | P | 0 | 0 | <ID_покормить> | | 0
Между воздействиями при необходимости увеличить интервал (StateHoldPlusOne), чтобы стили/состояние
успели отразиться в логе.

--------------------------------------------------------------------------------
3.2. Стадия 2 — «обычные» автоматизмы и дерево (без зеркала стадии 3)
--------------------------------------------------------------------------------
Механизм: AutomatizmSystem, AutomatizmTree, AutomatizmChainsSystem; загрузка примитивов
Stage2PrimitivesLoader (отдельно от сценария — из файла шаблона стадии 2).

Идея сценария: после перехода на стадию 2 и загрузки/формирования цепочек подавать новые короткие
фразы, не совпадающие с примитивами, затем повторять — ожидать появление/запуск автоматизмов
в колонке Automatizm; при двухступенчатых реакциях — CondRef и цепочку АВ.

Пример:
  1 | 1 | P | 0 | 0 | | слово_А | 0
  2 | … | P | 0 | 0 | | слово_Б | 0
  3 | … | P | 0 | 0 | | слово_А | 0   (проверка восстановления по триггеру)
Паузы между шагами взять ActionHoldPlusOne или больше, если автоматизм длинный по пульсам.

--------------------------------------------------------------------------------
3.3. Стадия 2 — преобразование условного рефлекса в автоматизм
--------------------------------------------------------------------------------
Механизм: ConditionedReflexToAutomatizmConverter (при смене стадии 1→2 в типичном сценарии жизни).

Идея: в два этапа нельзя в одном .dat без смены стадии; для интеграционного теста — сценарий
на стадии 1 с наращиванием CondRef, затем ручной/отдельный прогон после перехода на стадию 2
с той же CS-фразой; ожидание — колонка CondRef падает, Automatizm отражает перенос.

Последовательность на стадии 2 (после переноса):
  1 | 1 | P | 0 | 0 | | <учёная_CS_фраза> | 0
  2 | … | P | 0 | 0 | | другая_фраза | 0

--------------------------------------------------------------------------------
3.4. Стадия 3 — ориентировочный рефлекс и связка с автоматизмами
--------------------------------------------------------------------------------
Механизм: OrientationReflexSystem (активная логика при стадии ≥ 3 в части веток PsychicSystem).

Идея: серия новых вербальных стимулов подряд с достаточным интервалом; в ожиданиях — OrUm,
переключение Trigger, возможная активация автоматизма после OR.

Пример:
  1 | 1 | P | 0 | 0 | | уникальная_строка_1 | 0
  2 | … | P | 0 | 0 | | уникальная_строка_2 | 0
  3 | … | P | 0 | 0 | | уникальная_строка_1 | 0

--------------------------------------------------------------------------------
3.5. Стадия 3 — тон и настроение в вербальном стимуле (если канал их учитывает)
--------------------------------------------------------------------------------
Механизм: вербальный канал / примитивы стадии 2 с NotFoundToneOrMood; на стадии 3 — влияние на
разбор стимула при ненулевых ToneId, MoodId.

Идея: одна и та же фраза с разными ToneId|MoodId на соседних шагах; сравнить лог (Trigger, Style).

Пример:
  1 | 1 | P | 1 | 0 | | тестовая_фраза | 0
  2 | … | P | 0 | 1 | | тестовая_фраза | 0

--------------------------------------------------------------------------------
3.6. Стадия 3+ — комбинированный шаг: фраза + пульт воздействий
--------------------------------------------------------------------------------
Механизм: совместная обработка VerbalSensorChannel и гомеостаза (реальный путь TryApplyScenarioStimulus).

Идея: одна строка с непустой Phrase и непустым ActionIds (если движок допускает — валидатор
разрешает оба).

Пример:
  1 | 1 | P | 0 | 0 | 5 | текст_одновременно | 0

--------------------------------------------------------------------------------
3.7. Стадия 3+ — только сброс ожидания без стимула vs шаг W
--------------------------------------------------------------------------------
Механизм: OperatorScenarioRunner — ResetWaitingPeriod и Kind=W оба вызывают cancelWaitingPeriod;
различие: W не требует стадии 3 для «чистоты» валидатора, ResetWait=1 — только со стадии 3.

Сравнительный тест (два микросценария):
  A) 1 | 1 | W | 0 | 0 | | | 0
  B) 1 | 1 | P | 0 | 0 | | | 1   (только ResetWait, без фразы и действий — допустимо по правилам)

--------------------------------------------------------------------------------
3.8. Стадия 4 — главный цикл мышления, тема, дерево понимания
--------------------------------------------------------------------------------
Механизм: ThinkingCyclesSystem, ProblemTreeSystem, ThemeImageSystem, ThinkingThemePulseResolver;
лог — колонки Theme, Cycle (Цикл М).

Идея: длиннее прогон с нерешённой ситуацией (вербальные стимулы, возможно пульт «затруднить»);
ожидания на поздних шагах — ненулевой Cycle, смена Theme. Конкретные ID задаются из данных проекта.

Пример каркаса (много шагов, пульсы с Sequential или StateHoldPlusOne):
  1..N | возрастающие | P | 0 | 0 | (по очереди пусто / воздействия) | фразы_проблемы | 0

--------------------------------------------------------------------------------
3.9. Стадия 4 — эпизодическая память
--------------------------------------------------------------------------------
Механизм: EpisodicMemorySystem (в PsychicSystem связан с pulseCount == 2 и далее при стадии ≥ 4).

Идея: повторить осмысленную последовательность стимулов дважды с большим интервалом — вторая
половина должна показать отличие в обработке (поиск в памяти); в логе смотреть побочные маркеры
и стратегии, если включены в отчёт.

--------------------------------------------------------------------------------
3.10. Стадия 4–5 — стратегия «спросить оператора» (AskOperatorStrategy)
--------------------------------------------------------------------------------
Механизм: при недостатке опыта цикл мышления может ждать внешнего стимула.

Идея: короткая фаза без ответа, затем шаг с P|фраза после появления в логе признака ожидания;
проверка снятия блокировки и продолжения Cycle.

--------------------------------------------------------------------------------
3.11. Режим наблюдения и авторитарная запись (метаданные сценария, не строка шага)
--------------------------------------------------------------------------------
Механизм: флаги ScenarioObservationMode и ScenarioAuthoritativeRecording — поведение пульта
при прогоне; влияет на обучение безусловным/условным путём и запись фраз.

Идея: два одинаковых набора строк шагов, но разные флаги в SCENARIO_META; сравнить CondRef/автоматизмы.

--------------------------------------------------------------------------------
3.12. Начальные значения гомеостаза (InitialHomeostasisValues в шапке)
--------------------------------------------------------------------------------
Механизм: ScenarioHomeostasisValuesFormat — задание id=value до первого шага.

Идея: сценарий с одним тем же воздействием при разных стартовых параметрах — разные пороги
рефлекса/стиля; проверка State/Style в первом же шаге.

--------------------------------------------------------------------------------
3.13. Стадия 4+ — важность объектов (ObjectImportanceService)
--------------------------------------------------------------------------------
Механизм: начисление важности при эволюции ≥ 4.

Идея: серия повторов одного стимула с эмоционально значимыми воздействиями; косвенно — через
Style/Theme/длину цикла (уточнять по фактическим полям лога в вашей сборке).

--------------------------------------------------------------------------------
3.14. Цепочки рефлексов и автоматизмов (столбцы «Цепочка РФ», «Цепочка АВ»)
--------------------------------------------------------------------------------
Механизм: ReflexChain, AutomatizmChain в логе.

Идея: спроектировать подряд два близких по времени воздействия (вербал + пульт), укладывающихся
в настройки цепочки; ожидания в SCENARIO_LOG_EXPECTATIONS заполнить по эталонному прогону.

Пример микросценария:
  1 | 1 | P | 0 | 0 | | слово | 0
  2 | 2 | P | 0 | 0 | <ID_UCR> | | 0

--------------------------------------------------------------------------------
3.15. PurposeGeneticSystem (стадии 2–3+)
--------------------------------------------------------------------------------
Механизм: связь генетических целей с автоматизмами и рефлексами.

Идея интеграционного теста: сценарий на стадии 3 с воздействиями, меняющими «целевой» контекст,
плюс вербальные якоря; проверка по специализированным полям лога, если они экспортируются в таблицу
ожиданий (при отсутствии колонки — ручной разбор HTML-отчёта).

4. ЗАМЕЧАНИЯ ПО ПРАКТИКЕ

- Все ID действий и тексты фраз должны существовать в конфигурации агента и вербального канала;
  иначе шаг не пройдёт валидацию или даст пустой эффект.
- Пульсы в файле должны строго возрастать от шага к шагу; дубликаты запрещены валидатором.
- Сброс ожидания (ResetWait=1) нельзя смешивать с фразой/действиями на одном шаге.
- Для стадий 4–5 сценарии станут длинными: имеет смысл включить Sequential (приращение 1), чтобы
  экономить общее число пульсов, либо наоборот StateHoldPlusOne для устойчивых состояний.
