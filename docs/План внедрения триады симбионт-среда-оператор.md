# План поэтапного внедрения триады «симбионт — среда — оператор» в движок ISIDA

**Дата:** 2026-05-24 (актуализация §1)  
**Основание:** «Архитектура движка isida.txt» v3.8 (§0–§13)  
**Целевой код:** `D:\ISIDA\Programms\isida` (сборка V3.2), хост `AIStudio`  
**Статус:** рабочий план разработки (не канон; канон — исходный документ архитектуры). **Этапы 0–4 и 6 закрыты в коде** (см. §10) в виде MVP; **целевая среда** — реактивный симbiont стадий **0–1** (§11); post-MVP Creature — этап 5.

**Определение среды (финализировано 2026-05-24):** Niche = **универсальный** реактивный симbiont стадии 0 (гомеостаз + безусловные рефлексы) **+ опционально стадия 1** (условные рефлексы). **Без психики, без автоматизмов, без стадий 2+.** Привязка к конкретной внешней среде — **не в движке**, а в проекте AIStudio: справочники `Data/Niche/` и конфиг `Environment/`. Профиль `niche_reactive` (automatisms) из ранних черновиков **не используется**.

**Про сроки:** в §8 две колонки — «реализация кодом (AI + вы)» и «календарь команды». Недели в исходной версии относились ко второму: ревью, ручные прогоны в AIStudio, калибровка параметров, эксперименты на живом агенте. Сам код движка и базовая интеграция — часы, не недели.

### 1.3. Текущая схема (триада, реализовано)

```
Operator ──AssessmentType, сценарии──► (форма, ритуал)
                │
                ├── (фаза A–B) ──InfluenceAction──► Creature (GomeostasSystem)
                └── (фаза C, стадия 4+) ──operator_niche_coupling──► Niche

Creature ──ApplyAction──► CouplingBridge ──► Niche (NicheHostState / NicheEngine)
                              │
TriadOrchestrator.ProcessTriadPulse ──mapping──► Creature (HostBatchUpdate, StimulusOrigin=Niche)
                              │
Creature ──AOE──► Δгомеостаз (фаза B+: первично от Niche через AoeEvaluationService)
```

Порядок такта: `TriadOrchestrator` → `GomeostasSystem.UpdateStateOnly` → стимул Operator → `PsychicSystem` (§12.3).

## 2. Принципы внедрения

**Обязательное условие перед любым этапом:** прочитать и соблюдать правила проектов:

- `D:\ISIDA\Programms\isida\.cursor\rules\` — стандарты классов, IsidaEngine, без `*.Instance`, C# 7.3, XML-документация, явное включение в `isida.csproj`
- `D:\ISIDA\Programms\app\AIStudio\.cursor\rules\` — MVVM, C# 7.3, интеграция через `IsidaContext`, XAML (ComboBox без ItemTemplate)

1. **Инкрементальность:** сначала MVP-диада на хост-хуках (этап 0–1), затем AOE (этап 2), затем полноценный Niche-движок (этап 4).
2. **Без legacy-форматов:** проект в стадии развития — новые `.dat`/конфиги вводятся в актуальном формате, поддержка старых схем не требуется.
3. **Разметка для исследователя:** `StimulusOrigin`, лог диады — не в конвейере восприятия Creature.
4. **Один такт — один порядок:** `Niche.Update → Coupling → Creature.Update` (§6.5).
5. **Песочница → эксплуатация:** фазы A → B → C по нарастающей автономии Niche (§0.7).
6. **Среда = реактивный симbiont 0 (+ опц. 1):** без Psychic, без automatisms; те же классы и формат файлов, что у Creature, каталог `Data/Niche/`.
7. **Фаза ↔ стадия Creature:** допустимый диапазон фазы задаётся стадией **Creature** (§4.1, `TriadPhaseStagePolicy`); стадия Niche ограничена 0–1 независимо.

| **Post-MVP** (+ этап 5) | **+0.5–1 день** |

Первый инкремент из §10 (CouplingBridge + лог диады, без смены AOE) — **~2–4 часа** одной сессии.

### 8.2. Что не укладывается в «несколько часов»

Это не про скорость набора кода, а про **верификацию поведения**:

- ручные прогоны сценариев на стадиях 2–4 и проверка, что automatizm реально учится от Niche, а не от Operator;
- подбор threshold, N, K, W_eval на ваших данных гомеостаза;
- регрессия старых сценариев Operator и зеркала;
- эксперимент переноса Niche₁→Niche₂ (§6.6) — несколько серий прогонов, не один коммит.

Календарь здесь — **дни–недели по вашему темпу тестирования**, не по объёму C#.

## 11. Этап 7. Реактивный симbiont-среда (целевая архитектура)

**Определение:** Niche = **универсальный** реактивный симbiont **стадии 0** + **опционально стадия 1**. Никакой психики, automatisms, зеркала, эпизодики, мышления. Возможное упрощение в будущем: только стадия 0.

**Универсальность vs экземпляр:** движок и классы не знают «SolidWorks», «офис» или иной контур. Конкретная среда задаётся **данными проекта**: справочники гомеостаза и рефлексов в `Data/Niche/`, coupling/mapping/contour в `Environment/`. Смена предметной области = новый набор `.dat` в Studio, без правки кода Niche.

### 11.1. RoleProfile Niche

| Профиль | Стадия Niche | Подсистемы | Данные |
|---------|--------------|------------|--------|
| `niche_stage_0` | 0 | `GomeostasSystem` + `GeneticReflexesSystem` | `Data/Niche/Gomeostas/`, `Data/Niche/Reflexes/` (genetic) |
| `niche_stage_1` | 0–1 | + `ConditionedReflexesSystem` (ограниченно) | + conditioned lists, settings |
| `creature_full` | 0–5 | полный стек | `Data/` |

Coupling, mapping, contour — по-прежнему **`Environment/`** (слой эксперимента, не «физиология» Niche).

### 11.2. Задачи этапа 7

| # | Задача | Результат |
|---|--------|-----------|
| 7.1 | Второй `IsidaEngine` / `IsidaContext` для Niche | Тот же код инициализации, `BaseDirectory` → `Data/Niche/` |
| 7.2 | `RoleProfile` только 0–1 | Gate: Psychic, Automatizm*, Mirror, Episodic, Thinking — **запрещены** для Niche |
| 7.3 | Такт Niche | `GomeostasSystem.UpdateStateOnly` Niche → coupling/reflex → mapping → Creature |
| 7.4 | Миграция с `NicheHostState` | Feature flag; deprecate `niche_params.dat` → `VitalParameters.dat` |
| 7.5 | Coupling → гомеостаз Niche | `ApplyAction` / Operator / contour → `InfluenceAction` или host-batch на **Niche.GomeostasSystem** |
| 7.6 | Рефлексы Niche | Полные БР (+ опц. УР) вместо `NicheReflexLayer` / `niche_reflexes.dat` |
| 7.7 | AIStudio | Редактор гомеostаза/рефлексов **среды** (те же страницы, корень `Data/Niche/`) |
| 7.8 | Шаблон проекта | `ProjectBootstrap`: зеркало структуры `Data/` → `Data/Niche/` (без Psychic/) |
| 7.9 | Изоляция состояния | Niche без `AppGlobalState` Creature; отдельный evolution stage Niche (0 или 1) |
| 7.10 | Регрессия | Фазы A–C, перенос §6.6, сценарии валидации без изменения coupling-топологии |

### 11.3. Критерий готовности

- Niche в Studio — **настраиваемый универсальный** реактивный симbiont: те же редакторы и форматы, что у Creature, корень `Data/Niche/`.
- Экземпляр среды (любой контур) собирается заполнением справочников + `Environment/`; движок не меняется.
- Перенос Niche₁→Niche₂ и contour sim→real без смены coupling-топологии.
- Creature — единственный обучающийся агент (AOE, automatisms).

### 11.4. Порядок работ (кратко)

1. **Контракт данных** — зафиксировать `Data/Niche/` = копия **структуры** `Data/` (Gomeostas, Reflexes), без Psychic.
2. **Второй движок** — `IsidaEngine.Create` с `RoleProfile.niche_stage_0`, отдельный pulse hook в `TriadOrchestrator`.
3. **CouplingBridge** — вместо `NicheHostState` вызывать гомеостаз/рефлексы Niche-engine.
4. **UI** — режим «Среда»: те же страницы гомеостаза/рефлексов, корень `Data/Niche/`; оператор заполняет справочники под выбранный контур.
5. **Пилотный проект** — любой учебный контур: 8–12 VitalParameters, БР, coupling, mapping на Creature; без изменения движка.
6. **Deprecate** — `NicheHostState`, `niche_params.dat`, `niche_reflexes.dat` после миграции.
