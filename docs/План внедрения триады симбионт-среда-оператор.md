### 1.2. Критические разрывы (блокируют триаду)

| Компонент канона | Код §12 | Последствие |
|------------------|---------|-------------|
| Niche как симбионт-среда | ❌ | Operator совмещает роли среды и судьи |
| `CouplingBridge` + `CouplingTarget` | ❌ | Действия Creature не меняют Niche |
| Отображение Niche → Creature | ❌ | Нет каузальной обратной связи среды |
| `StimulusOrigin` | ❌ | Нельзя разделить каналы Operator/Niche в AOE |
| `AssessmentType` + фазовые ограничения | ❌ | Нет угасания Operator на стадиях 4+ |
| Baseline / `niche_response_delta` | ❌ | AOE смешивает фон и отклик Niche |
| Исходы AOE: NoResponse / Ambiguous | ❌ | Нейтральный ноль по умолчанию |
| Niche-primary AOE | ❌ | Обучение «угождению оператору», не адаптации к среде |
| `RoleProfile` для Niche | ❌ | Нет редуцированного стека среды |
| Второй экземпляр движка (Niche) | ❌ | Один `GlobalTimer` / `AppGlobalState` |
| Eligibility trace, forward model runtime | ❌ | Длинные цепочки и предиктивный выбор — post-MVP |

### 1.3. Текущая схема vs целевая триада

**Сейчас (диада):**

```
Operator ──InfluenceAction──► Creature (гомеостаз, AOE по ответу Operator)
                │
                └── (иногда) хост-хук ──► параметры Creature
```

**Цель (триада, MVP-диада):**

```
Operator ──AssessmentType, сценарии──► (форма, ритуал)
                │
                └── (фаза C) ──► Niche ──coupling──► Creature

Creature ──ApplyAction──► CouplingBridge ──► Niche (гомеостаз)
                              │
Niche.Update ──mapping──► Creature (HostBatchUpdate, StimulusOrigin=Niche)
                              │
Creature ──AOE──► Δгомеостаз (первично от Niche, не от Operator)
```

## 2. Принципы внедрения

**Обязательное условие перед любым этапом:** прочитать и соблюдать правила проектов:

- `D:\ISIDA\Programms\isida\.cursor\rules\` — стандарты классов, IsidaEngine, без `*.Instance`, C# 7.3, XML-документация, явное включение в `isida.csproj`
- `D:\ISIDA\Programms\app\AIStudio\.cursor\rules\` — MVVM, C# 7.3, интеграция через `IsidaContext`, XAML (ComboBox без ItemTemplate)

1. **Инкрементальность:** сначала MVP-диада на хост-хуках (этап 0–1), затем AOE (этап 2), затем полноценный Niche-движок (этап 4).
2. **Без legacy-форматов:** проект в стадии развития — новые `.dat`/конфиги вводятся в актуальном формате, поддержка старых схем не требуется.
3. **Разметка для исследователя:** `StimulusOrigin`, лог диады — не в конвейере восприятия Creature.
4. **Один такт — один порядок:** `Niche.Update → Coupling → Creature.Update` (§6.5).
5. **Песочница → эксплуатация:** фазы A → B → C по нарастающей автономии Niche (§0.7).
6. **Фаза ↔ стадия:** допустимый диапазон фазы задаётся стадией симбионта (§4.1, `TriadPhaseStagePolicy`); сохранение недопустимой фазы отклоняется, при смене стадии — auto-clamp.

### 8.2. Что не укладывается в «несколько часов»

Это не про скорость набора кода, а про **верификацию поведения**:

- ручные прогоны сценариев на стадиях 2–4 и проверка, что automatizm реально учится от Niche, а не от Operator;
- подбор threshold, N, K, W_eval на ваших данных гомеостаза;
- регрессия старых сценариев Operator и зеркала;
- эксперимент переноса Niche₁→Niche₂ (§6.6) — несколько серий прогонов, не один коммит.

Календарь здесь — **дни–недели по вашему темпу тестирования**, не по объёму C#.

### Шаги первого инкремента

1. Создать `Environment/TriadModels.cs` (`StimulusOrigin`, `AssessmentType`, `CouplingTarget`).
2. Реализовать `CouplingBridge` + загрузка `coupling_mapping.dat`.
3. Подключить в `GlobalTimer`: после hook — apply mapping Niche→Creature с логом origin.
4. Расширить `ResearchLogger` одной строкой диады на пульс.
5. Добавить интеграционный тест: action → Δ Niche → Δ Creature (без изменения AOE).

После этого инкремента система остаётся в режиме operator-centric AOE, но **каузальный контур Creature↔Niche** уже измерим в логах — минимальная проверка архитектуры триады. Дальше этап 2 (Niche-primary AOE) — ещё одна сессия ~4–8 ч.
