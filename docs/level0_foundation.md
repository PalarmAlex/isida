# Уровень 0: база и критерии (документация)

Связь с [HIGHER_PSYCHIC_PHENOMENA_ROADMAP.md](HIGHER_PSYCHIC_PHENOMENA_ROADMAP.md).  
Этот файл фиксирует **три** результата уровня 0: операциональное определение стадии 5, **карту состояния субъекта** и **чек-лист** приёмки. Код **не** меняется; при смене полей/сервисов таблицу в §2 и чек-лист в §3 **обновлять**.

---

## 1. Операциональное определение стадии 5 (Сознание)

**Позиция:** ветка в коде с условием `AppGlobalState.EvolutionStage == 5` **практически не выделена**; большинство «высоких» механизмов (психика, УМ, циклы, эпизодика) ограничены **`>= 4`**. Стадия 5 в `EvolutionStageService` сейчас **именование** (продуктовая цель) поверх **технической** зрелости стадии 4+.

**Операционное определение (приёмка):** агент на **стадии 5** считается **настроенным на пакет «сознательного контура»**, если одновременно:

| Требование | Смысл | Как проверить |
|------------|--------|----------------|
| `IsidaEngine` полностью инициализирован, `AppGlobalState.EvolutionStage == 5` | Стадия выбрана явно | Запуск приложения / сценарий, чтение текущей стадии |
| `PsychicSystem` активен, пульс мира идёт | «Сознательный» контур **не** отделён в отдельный процесс | Сессия 1+ пульс без фатала |
| `InformationEnvironmentSystem` доступен, `CurrentInformationEnvironment` обновляется | Интегративный кадр ситуации (IE) | Лог/отладчик: поля `Danger`, `Mood` и т.д. меняются с контекстом |
| `ThinkingCyclesSystem` инициализирован на стадии 4+ (см. `IsidaEngine` / `ThinkingCyclesSystem`) | Диспетчер **циклов** мышления | На стимулах, где сценарий требует циклов, нет «null» диспетчера |
| `EpisodicMemorySystem` и `EpisodicMemoryRulesService` **разрешены** (стадия `>= 4` в сервисе правил) | Эпизодическое **обучение/правила** | Запись эпизода/правила **без** предупреждения о недостаточной стадии |
| Уровни УМ1/УМ2: `ProcessLevel1` / `ProcessLevel2` в `PsychicSystem` при **стадии 4+** | **Осмысление** (штатный автоматизм → правила) | Сценарий, где L2 **может** сработать (есть эпизод/правило) |
| `ResearchLogger` (или аналог) пишет снимок состояния на пульс | **Воспроизводимая** **след** для сравнения | Два прогона одного сценария: структура лога **согласуема** (доп. недетерминизм зафиксировать) |

**Примечание:** до появления **отдельного** `if (EvolutionStage == 5) { ... }` стадия 5 = **супермножество** стадии 4 **по функциям** + **обязательства** к документированной приёмке и сценариям из §3, а **не** новой ветки в движке. Когда **появятся** **уникальные** для 5 **флаги/сервисы** (например, «ментальная память») — **дополнить** эту таблицу.

## 2. Единая карта состояния субъекта (источник правды для самоотчёта)

Цель: один **смысловой** срез «что **сейчас** значит для агента ситуация» с указанием **класса**, где **лежит** поле. Роль **самоотчёта** (аналог `GetSelfPerceptionInfo` в BOT) на уровне 1 **реализуется как экспорт** этих полей; **здесь** — канон **имен** и **смыслов** (сверять с XML-комментариями в коде).

### 2.1. Интегративная среда (`InformationEnvironment` в `InformationEnvironmentSystem`)

| Поле | Назначение (кратко) |
|------|---------------------|
| `LifeTime` | Время/пульс кадра (если проставляется) |
| `IsPsyLevel` | Кадр со стороны психики |
| `IsSleep` | Сон: контекст IE в спящем режиме |
| `IsIdleness100pulse` | Пассив: давно не было действий с пульта |
| `Mood` | Интегральное гомео-настроение |
| `CurTargetArrID` | Целевые параметры гомеостаза |
| `PsyEmotionId` | Текущая эмоция (картинка) |
| `Danger` | Опасная зона по жизненным параметрам |
| `VeryActualSituation` | «Срочно» / важность ситуации |
| `PsyMood` | Субъективное настроение (с инерцией) |
| `ActionsImageID` | Образ стимула/действия с пульта |
| `IsUnknownActionsImageID` / неизвестность | Беспокойство, пассив |
| `AnswerImageID` | Образ **ответа** моторного автоматизма |
| `IsWaitingPeriod` | Ожидание оценки от оператора |
| `ExtremImportanceObjectID` | Фокус по **значимости** (объект) |
| `ActualEpisodicMemoryID` | Узел/правило эпизодики, вытянутое вниманием |
| `DominantaID` | Нерешённая доминанта (в терминах модели) |
| `NeedThinkingAboutAutomatizm` | Метанужда «подумать/инициатива» |
| `IsStimulToForce` | Стимул против **темы/цели** |
| `UnresolvedAtThinkingLevel2` | L2 **не** закрылся |
| `UnresolvedNodeId`, `UnresolvedActionsImageId`, `UnresolvedPulseCount` | Контекст нерешённости L2 |

**Кадры в памяти:** `InformationEnvironmentSystem.InformationEnvironmentObjects` + `Current` / `Old` (кратковременная **лента** — уже есть; **размер/политика** очистки при сне — в уровне 2 дорожной карты).

### 2.2. Глобальное и лог-контекст (не дублировать IE без причины)

- **`AppGlobalState`:** стадия эволюции, `WaitingForOperatorEvaluation` (и связанные), последний `LastTriggerStimulusID`, `CurStimulusImageId` и т.д. **Сверяться** с `InformationEnvironment` при **конфликте** по **правилу**: для **психического** «самочувствия» в приоритете **текущий** кадр IE, для **триггера** рефлекса — что зафиксировано **в активаторе** (см. документационные ссылки в `ResearchLogger`).

- **`ResearchLogger` / `SystemState`:** колонки **Опасно/Актуально**, автоматизм, эпизод, цепочки — **проекция** для **исследования**; **не** объявлять **единственным** источником без **сшивки** с IE в коде (уровень 1: экспорт самоотчёта).

### 2.3. Стадия 5 (операционно)

- **Субъективно значимое** на стадии 5: **тот же** набор, что **для 4+**, **пока** нет отдельного «слоя 5» в типах. Дополнения — только **после** **новых** полей в IE или отдельном DTO (уровни 1–2 дорожной карты).

## 3. Сценарии и чек-лист приёмки (регрессия вручную)

Состояния **галочками** по мере **подготовки** сценариев. Имена **обобщённые**; конкретные `Scenario_*.dat` **добавляются** в пункты по мере появления.

| # | Сценарий (смысл) | Минимальные условия (стадия) | Критерий «пройдено» |
|---|------------------|-----------------------------|----------------------|
| C1 | Главный / фоновый цикл мышления | 4+, пульс, `ThinkingCyclesSystem` | В логе/снимке видно: есть **главный** и при наличии — **фон** (по `ThinkingCyclesSystem` / `PublishedBackgroundThinkingCycleSnapshot`) |
| C2 | Сон / пробуждение | Настраиваемый сон, IE | `IsSleep` / кадр IE **меняется**; после **просыпания** **нет** **утечки** **битого** контекста (если **ожидаемо** очищено) |
| C3 | Смена **темы** по **триггеру** | Understanding, каталог событий | `UnderstandingTreeSystem` / `UpdateThemeByTrigger` — **тема** **сменилась** при событии **в сценарии** |
| C4 | **Неразрешимость** (L2), постановка `Unresolved*`) | 4+, эпизодика/правила по сценарию | `UnresolvedAtThinkingLevel2 == true` **в ожидаемый** **момент**; `UnresolvedNodeId` **не 0** при **заданной** **проблеме** |
| C5 | **Отложенная оценка** оператором (окно ожидания) | 2+ автоматизмы, оценка | `IsWaitingPeriod` / `AppGlobalState.WaitingForOperatorEvaluation` **согласованы**; после **ответа** **корректный** **переход** |
| C6 | **Эпизодическое** правило **влияет** на **выбор** (УМ2) | 4+, записанное **правило** | `ProcessLevel2` **подхватывает** **правило**; в логе **виден** **источник** (`GetTargetChain` / `GetSingleBestRule`) **по** **документ** **отладчика** |

**Дополнительно (после стабилизации):** сценарий **«сознательного»** **снимка** = C1 + C4 + C5 + **согласованные** **колонки** `ResearchLogger` **на** **одном** **длинном** **прогоне**.

## 4. Порядок исполнения уровня 0 (чеклист команды)

1. Утвердить §1 (операционное определение) — **1 обзор** с владельцем ядра.
2. Сверить §2 с **актуальными** свойствами `InformationEnvironment` (diff при рефакторе).
3. **Заполнить** таблицу §3 **ссылками** на `Scenario_*.dat` / шаги пульта по **мере** **появления** сценариев.
4. Добавить **ссылаясь** на §2, на уровне 1: **один** **модуль/метод** **самоотчёта** (не продублировать §2 в **два** **конкурирующих** **дока**).
5. При **релизе** **изменений** **IE** — **обновить** §2 и **при** **нужно** **§1**.
