# Дорожная план: высшие психические феномены в ISIDA

План доработок **от простого к сложному** для приближения к **операциональным** суррогатам феноменов, которые в когнитивной науке и философии относят к «сознанию», **самоидентификации**, **рефлексии** и **целенаправленной воли**. Ориентиры по смыслу: интегративная информационная среда, эпизодическое обучение, диспетчер мышления (ср. схемы в родственном проекте BOT, см. `isida_episodic_memory_plan.txt` в репозитории BOT / исторический план переноса в ISIDA).

**Важно:** «Сознание» здесь не требуется в метафизическом смысле; цель — **согласованные, сценарно проверяемые** механизмы, которые **измеримо** ведут себя как: единая картина ситуации, субъективный отчёт, внимание (главное/фон), автобиографическая целостность, метакогнитивные решения (думать/отложить/инициативу).

---

## Уровень 0. База и критерии (без крупного кода)

**Сводная реализация и чек-лист команды:** [level0_foundation.md](level0_foundation.md).

1. **Операциональное определение стадии 5**  
   Зафиксировать, какие подсистемы **обязаны** быть инициализированы, какой **сценарий/метрика** для приёмки («сознательный» сценарий = минимум: IE + эпизодика + уровни мышления + отчёт о состоянии).

2. **Единая «карта состояния субъекта» для отладки и пульта**  
   Свести в одно описание: `InformationEnvironment` + `AppGlobalState` + снимок из `ResearchLogger` → что считаем **текущим субъективно значимым** (настроение, опасность, актуальность, нерешённая проблема, ожидание оценки, доминанта при наличии).  
   Цель: **один** источник правды для **самоотчёта** (аналог смысла `GetSelfPerceptionInfo` в BOT — не копия кода, а **роль** в продукте).

3. **Сценарии приёмки** (регрессия)  
   Добавить/уточнить **чек-лист** вручную или в сценариях: главный/фоновый цикл, сон/просыпание, смена темы по триггеру, «путаница»/неразрешимость, отложенная оценка.

## Уровень 1. Простые, но полезные укрепления (низкий риск)

4. **Экспорт «самоописания»**  
   Формальный **текст/JSON/блок** для пульта или внешнего API: краткое **перволичное** описание текущего кадра (гомеостаз, настроение, danger/actual, **если** есть: активный узел проблемы, тема, `ExtremImportance` при использовании).  
   Критерий: то же переживание можно **прогнать дважды** — отчёт **детерминированно** воспроизводим при том же снимке.

5. **Согласованность нумерологии когнитивного контура**  
   Устранить расхождения в **именах стадий** (например, UМ2 и эпизодика **только** 4+ в коде), задокументировать в `README` или `docs/`, чтобы «стадия 5: сознание» не путалась с «всё уже работает с пульта».

6. **Метки метасостояний**  
   Явно **именовать** и **логировать** уже существующие: `NeedThinkingAboutAutomatizm`, `UnresolvedAtThinkingLevel2`, `WaitingForOperatorEvaluation`, **лень/ожидание** (если есть аналоги) — **один** читаемый блок в логе/отчёте, без новой сложной логики.

## Уровень 2. Инфраструктурная зрелость (средняя трудоёмкость)

7. **Кратковременная «лента» информационной среды**  
   Хранение **последних N кадров** `InformationEnvironment` (или сжатых снимков) **только в RAM**: для сна, пассивного мышления, «вспомнить недавнее», выбора темы.  
   Очистка при **сон** — явная **санитария** (как в идее BOT: IE не плодить вечно).

8. **Завершение связи «дерево проблем ↔ эпизодика»**  
   По `isida_episodic_memory_plan.txt`: `NodePID` / активная ветка = **согласована** с узлами эпизодического дерева; **нет** сиротских правил «без» проблемного контекста, где это **заложено** в модель.

9. **Доминанта / фокус внимания (минимальная спецификация)**  
   Один **идентификатор** «текущей нерешённой линии» (проблема+тема или эквивалент), с **правилом** обновления при **новом стимуле** (новая линия может **суперседить** старую или **стекаться** в фон — **политика** настраиваема и **задокументирована**).

10. **Диспетчер: главный цикл мышления vs фон**  
   Усиление **существующей** `ThinkingCyclesSystem`: **явно** (в логе/отчёте) различать главный/фоновый циклы, **снятие** с главного по стимулу, **сопоставимо** с идеей «с каждым стимулом — свой цикл, старые в фон» (см. BOT: не обязанно буквально копировать, но **поведение** сценариев согласуется с документом).

## Уровень 3. Содержательные «высокие» феномены (сложно, дольше)

11. **Резерв `Psychic/Memory/Mental` (автобиографический слой)**  
   **Не** путать с моторной эпизодикой: краткие **само-нарративы** (шаблоны: «когда X, я обычно…»), **привязка** к `ActionsImage` / **цель** / **оценка полезности** во **времени** — **отдельное** хранилище и **отдельные** сценарии обучения.  
   Критерий: **устойчивый** **образ «я в контексте»** (операционно: retrieval по запросу «кто/в каком состоянии/под какой проблемой»).

12. **Сон, инсайт, пассивная обработка**  
   Согласованность: **сновидение** = выборка из **ленты** IE/эпизодики, **порог значимости** (аналог `insightCompare` в смысле: «обрывать» пассив и **переходить** в главный цикл / **протокол записи** двух кадров при «осознании»).  
   Чёткое **разграничение** — что пишем в **эпизодику** при **инсайте** vs **обычном** шаге.

13. **Нарративная идентичность (только после 11–12)**  
   Связь **ролей** (если вводятся) с **тематикой** и **ответственностями** в **диалоге**; **не** смешивать с моторной полезностью `Usefulness` **без** явной **шкалы** перевода.

14. **Стадия 5 «Сознание» как *пакет***  
   Активировать **только** при выполнении: (а) **лентa** IE, (б) **отчёт** субъекта, (в) **диспетчер** циклов с главным/фоном, (г) **ментальная**/автобиографическая **опора** (хотя бы **пустой** **API** + один **сухой** сценарий).

## Уровень 4. Исследовательский «верх» (долгий горизонт)

15. **Согласованная воля/инициативa**  
   **Явные** **правила**: когда **разрешать** **спонтанные** шаги (только **не** danger, **не** ожидание оценки, **и** `NeedThinkingAboutAutomatizm` = …). Сценарии **негативные** и **позитивные**.

16. **Интеграция с LLM (если используется в проекте)**  
   **Только** после **стабильного** **снапшота** IE + **главная** нить мыслей: иначе «рассуждения» **не** привязать к **симбионтной** **самости**.

17. **Сравнение с BOT/Beast (опционально)**  
   **Чек-лист** **функциональной** **эквивалентности** (без **переноса** **построчно**): полный список **ролей** `consciousnessElementary` / диспетчер / **IE+история** / **самоотчёт** — **галочка** **да/частично/нет** в isida.

## Порядок внедрения (кратко)

1. **Документация** (уровень 0) → 2) **самоотчёт** + **мета-лог** (1, 5–6) → 3) **лента** IE + **связь** проблема/эпизодика (7–9) → 4) **диспетчер/циклы** (10) → 5) **ментальная** **память** + **сон/инсайт** (11–12) → 6) **стадия** **5** (14) → 7) **долгий** **хвост** (15–17).
