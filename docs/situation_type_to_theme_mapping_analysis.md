# Анализ привязки тем к типам ситуаций (DefaultTypeDefinitions) по данным BOT

## Исходные данные ISIDA

В `SituationTypeSystem.cs` (строки 386–394) заданы дефолтные типы ситуаций с полем `ThemeTypeId` (-1 = не задано):

| Id | Описание (ISIDA)           | ThemeTypeId (сейчас) |
|----|----------------------------|----------------------|
| 1  | Ответное действие          | -1                   |
| 2  | Запуск автоматизма         | -1                   |
| 3  | Нужно осмысление           | -1                   |
| 4  | Экспериментировать         | -1                   |
| 5  | Игнор оператора            | -1                   |
| 6  | Стимул с пульта            | 4                    |

Ниже — какие темы в BOT соответствуют этим же ситуациям и что можно поставить в `ThemeTypeId` в ISIDA.

---

## Соответствие ситуаций ISIDA и BOT

В BOT типы ситуаций описаны в `understanding_situation_image.go` (комментарии к `SituationType` и функция `getCurSituationImageID()`):

- **1** — было ответное действие (ожидание ответа оператора, период не истёк).
- **2** — был запуск автоматизма ветки (есть автоматизм в ветке).
- **3** — ничего не делали, но нужно осмысление (нет узла дерева автоматизмов, nodeId == 0).
- **4** — всё спокойно, можно экспериментировать (дефолт, когда нет пульта и т.п.).
- **5** — оператор не прореагировал в течение периода ожидания (игнор).
- **6** в ISIDA — «Стимул с пульта» (в BOT это контекст пульта: настроение/кнопки 10–17, 20–37; для «стимула с пульта» как такового явно используется тема 4 или 11).

Логика выбора ситуации в ISIDA (`SituationImageSystem.ResolveSituationTypeId`) совпадает с BOT: те же приоритеты (ожидание ответа → ответное действие/игнор, наличие автоматизма в ветке, пульт, иначе эксперимент).

---

## Какие темы в BOT включаются при этих ситуациях

### 1. Ответное действие (ISIDA Id = 1)

- **BOT:** ситуация 1 выбирается, когда `LastRunAutomatizmPulsCount > 0` и период ожидания ещё не истёк — т.е. «ожидаем ответ оператора / только что было ответное действие».
- **Тема в BOT:** при действии оператора в `automatism_tree.go` в `afterTreeActivation()` выставляется `needRunNewTheme = 11` («Действие оператора»). При негативном эффекте ответа — `needRunNewTheme = 2` («Негативный эффект ментального автоматизма»). В `understanding_tree.go` затем вызывается `runNewTheme(needRunNewTheme, 2)`.
- **Итог для ISIDA:** для ситуации «Ответное действие» логично привязать тему **11** — «Действие оператора» (основной случай — реакция на ответ оператора). Альтернатива — оставить -1 и задавать тему отдельно по результату (хорошо/плохо), как в BOT через needRunNewTheme 11/2.

**Рекомендуемая привязка: ThemeTypeId = 11.**

---

### 2. Запуск автоматизма (ISIDA Id = 2)

- **BOT:** ситуация 2 — когда в ветке есть автоматизм (`currentAutomatizmAfterTreeActivatedID > 0`). Отдельного `runNewTheme` именно для «запуск автоматизма» в BOT нет; тема к этому моменту уже задана через `needRunNewTheme` (11 или 2) из `afterTreeActivation`.
- **Итог для ISIDA:** ситуация «Запуск автоматизма» — скорее нейтральная (система действует по правилу). В справочнике тем BOT/ISIDA есть **17** — «Улучшение настроения» (базовая/нейтральная тема при отсутствии проблемы). Можно привязать её для «всё идёт по плану, автоматизм сработал». Либо оставить **-1**, если не хотите менять тему при этой ситуации.

**Рекомендуемая привязка: ThemeTypeId = 17** (умеренная базовая тема) **или -1** (без смены темы).

---

### 3. Нужно осмысление (ISIDA Id = 3)

- **BOT:** ситуация 3 — когда `detectedActiveLastNodID == 0` (нет узла дерева автоматизмов), т.е. «ничего не делали, но нужно осмысление».
- **Тема в BOT:** в `understanding_functions.go` при непонимании (`isConfusion`) вызывается `runNewTheme(10, 1)` — тема **10** «Непонимание». В `someThemeDetection` при плохом и опасном состоянии тоже ставится тема 10 (вес 3). Для «нужно осмысление» без явной опасности тема 10 всё равно подходит (недоосмысленное, новизна).
- **Итог для ISIDA:** для «Нужно осмысление» логична тема **10** — «Непонимание».

**Рекомендуемая привязка: ThemeTypeId = 10.**

---

### 4. Экспериментировать (ISIDA Id = 4)

- **BOT:** ситуация 4 — дефолт в `getCurSituationImageID()` когда нет пульта и т.п.: «всё спокойно, можно экспериментировать».
- **Тема в BOT:** в `someThemeDetection` при хорошем настроении и контексте поиска ставится `runNewTheme(5, 5)` — тема **5** «Поисковый интерес» (любопытство, экспериментирование, набор опыта). Для «можно экспериментировать» это прямая параллель.
- **Итог для ISIDA:** для «Экспериментировать» логична тема **5** — «Поисковый интерес».

**Рекомендуемая привязка: ThemeTypeId = 5.**

---

### 5. Игнор оператора (ISIDA Id = 5)

- **BOT:** ситуация 5 — когда `(LastRunAutomatizmPulsCount + WaitingPeriodForActionsVal) < PulsCount`, т.е. истекло ожидание ответа оператора.
- **Тема в BOT:** в `automatizm_result.go` при «оператор не ответил в течение периода ожидания» вызывается `runNewTheme(7, 2)` — тема **7** «Игнорирование оператором». В `ThemeTypeStr` у 7 так и написано: «оператор не ответил в течение периода ожидания на важный запрос».
- **Итог для ISIDA:** для «Игнор оператора» однозначно подходит тема **7** — «Игнорирование оператором».

**Рекомендуемая привязка: ThemeTypeId = 7.**

---

### 6. Стимул с пульта (ISIDA Id = 6)

- **Уже задано в ISIDA:** ThemeTypeId = 4 — «Стимул с Пульта».
- **BOT:** при действии с пульта в `afterTreeActivation` выставляется `needRunNewTheme = 11` («Действие оператора»). В списке тем BOT тема 4 — «Стимул с Пульта», тема 11 — «Действие оператора» (текстовое общение с оператором). Оба варианта используются для «стимула с пульта»; в ISIDA выбран 4 — это согласовано с названием слота.

**Привязку оставить: ThemeTypeId = 4.**

## Сводная таблица (рекомендуемые ThemeTypeId для ISIDA)

| Id | Описание (ISIDA)   | ThemeTypeId (рекомендация) | Соответствующая тема в BOT/ISIDA                          |
|----|--------------------|----------------------------|----------------------------------------------------------|
| 1  | Ответное действие  | **11**                     | Действие оператора                                       |
| 2  | Запуск автоматизма | **17** или **-1**          | Улучшение настроения (базовая) / без смены темы          |
| 3  | Нужно осмысление   | **10**                     | Непонимание                                              |
| 4  | Экспериментировать | **5**                      | Поисковый интерес                                        |
| 5  | Игнор оператора    | **7**                      | Игнорирование оператором                                 |
| 6  | Стимул с пульта    | **4** (уже есть)           | Стимул с Пульта                                          |

Нумерация тем совпадает в ISIDA (`ThemeImageSystem.DefaultThemeTypesList`) и BOT (`ThemeTypeStr`): 1–17 те же по смыслу.

## Замечания

1. **Ответное действие (1):** в BOT тема при ответе оператора может быть 11 или 2 (если эффект негативный). Привязка 11 к типу ситуации даёт «по умолчанию» тему «Действие оператора»; смена на тему 2 при негативном эффекте может делаться отдельной логикой (как в BOT в `afterTreeActivation` по `effect < 0`).
2. **Запуск автоматизма (2):** в BOT для этой ситуации тема отдельно не ставится. Выбор 17 или -1 — вопрос политики: либо нейтральная «Улучшение настроения», либо не менять тему при этой ситуации.
3. Остальные привязки (3→10, 4→5, 5→7, 6→4) напрямую соответствуют тому, как в BOT включаются темы при тех же типах ситуаций.

Код не менялся — только анализ и рекомендации по значениям `ThemeTypeId` в `DefaultTypeDefinitions`.
